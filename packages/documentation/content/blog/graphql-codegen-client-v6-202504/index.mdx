[typescript-operations](https://the-guild.dev/graphql/codegen/plugins/typescript/typescript-operations) and [client-preset](https://the-guild.dev/graphql/codegen/plugins/presets/preset-client) v6 are now available, with a holistic overhaul of dependencies, configuration, and plugin interoperability to improve the developer experience.

- Less generated code
- Better type correctness and defaults
- Fewer dependencies, and simpler setup

## The main change

Previously, the low-level [typescript plugin](https://the-guild.dev/graphql/codegen/plugins/typescript/typescript) was used to generate all schema types, and the `typescript-operations` plugin referenced those types for input and variables types.

This caused a few issues:

- **All schema types were generated, even if unused**
  - Result: unnecessarily large output and confusing, extraneous types
- **Client and server plugins were indirectly coupled**
  - Result: slower iteration, as changes risked breaking other use cases
- **Configuration options were numerous, yet fragmented**
  - Result: verbose setups and reliance on additional plugins/presets

With v6, `typescript-operations` and `client-preset` are redesigned to address these problems:

- Generate schema types only when they are actually used
- Fully decouple from `typescript` and `typescript-resolvers`
- Provide better built-in support for common setups: one-file, multi-file, and near-operation-file. Read [typescript-operations setups](https://the-guild.dev/graphql/codegen/docs/migration/operations-and-client-preset-from-5-0#typescript-operations)

### Other notable changes

- Default persisted document hash algorithm is now SHA-256
- Improve type correctness and defaults: scalars, `@skip`/`@include` directives, field nullability
- Option revamps: `avoidOptionals`, `enumValues`, removed `preResolveTypes`
- CLI errors no longer fail silently
- Packages are ESM-first

Read [v6 migration guide](https://the-guild.dev/graphql/codegen/docs/migration/operations-and-client-preset-from-5-0)

## Bonus: support migrating from Apollo Tooling to GraphQL Codegen

GraphQL Codegen now supports migrating from [Apollo Tooling](https://github.com/apollographql/apollo-tooling) (`apollo client:codegen`).

This includes:

- `near-operation-file` preset compatibility
- Enum type compatibility
- Matching type naming conventions

Existing Apollo Tooling projects can switch with minimal manual changes.

Read [migration guide from Apollo Tooling to GraphQL Codegen](https://the-guild.dev/graphql/codegen/docs/migration/apollo-tooling)
